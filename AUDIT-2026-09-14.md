## Top 20 (the reply to Isadora)

1. Test admin `test-admin@rixey.invalid` exists in production with `is_admin`
   and a password committed in five files (`scripts/seed_test_users.mjs:88`,
   `trigger-sync.mjs:20`, `invite-vendors-to-portal.mjs:57`,
   `resolve-vendor-merges.mjs:29`, `tests/guest-list-renders.spec.js:38`).
   Also `test-couple@rixey.invalid` on a real wedding. Live check 14 Sep:
   7 "Playwright & Test" weddings (15 Apr, date 2026-10-12) and 7
   `playwright-*@rixey-test.invalid` users left behind by runs that never
   reached `afterAll`, plus `rls-v-*@rixey.invalid`, `test-couple` with its
   "Test & Couple" wedding (2029-06-09), and `test-admin` (is_admin, last
   sign-in 28 Aug). Delete all of them, take creds from env, and make the
   Playwright spec clean up in a `finally`.
2. Sage will read any couple's file to a caller with no token. `/api/chat:1543`
   falls back to `req.body.userId`; weddingAccess finds no wedding id in body or
   path and lets it through. `POST /api/sage-messages:10415` inserts
   `{user_id, content, sender}` from the body, so a message can be forged as
   Sage in any thread. Fix: `requireAuth` on `/api/chat`, `/api/welcome`,
   `/api/chat-with-file`, `/api/sage-messages`; drop the body fallback.
3. Write routes with no login at all: `manor-assets` POST/PUT/DELETE
   (10815/10853/10871, public bucket), `wedding-photos` PUT/DELETE
   (12317/12337, missing from `ROW_TABLES`), multipart routes
   `/api/seating/import:14373`, `/api/extract-contract:2472`, `/api/inspo:7036`,
   `/api/couple-photo:7248` (weddingAccess runs before multer so `req.body` is
   empty), and `/api/bar-recipes/extract-url:12144` fetches any URL (SSRF) and
   sends it to Claude.
4. weddingAccess trusts a wedding id in body/query over the row being edited
   (`weddingAccess.js:110-118`, `165-170`). A couple can `PUT
   /api/guests/<other guest id>?weddingId=<own>` and edit or delete another
   couple's guest. It also fails open on lookup errors (`178-181`, `208-212`)
   and caches a null profile for 15s on a read blip.
5. No `app.set('trust proxy')`, so every limiter keys on Railway's proxy IP and
   all users share one 500/15min bucket (`:145-175`). One looping tab empties
   it for everyone (the August "admin looks empty" shape). Event-code and
   guest-search limiters cannot tell an attacker from a couple.
6. Gmail and Quo only sync when someone presses the button (`Admin.jsx:236`,
   `:319`; no cron, no mount trigger). Only Zoom has a timer (`:14070`), added
   after exactly this bit. Emails and texts sit outside the portal until a
   human remembers.
7. A failed load can be autosaved back as blank defaults.
   `WebsiteBuilder.jsx:211` has no `res.ok` check; an error body has no
   `wedding_id`, so it takes the first-time branch, and the slug check flipping
   state fires autosave with `published:false` and empty fields. Same shape in
   `TimelineBuilder:795/905`, `BudgetTracker:67`, `RsvpSettings:20`,
   `RehearsalDinner:96`, `TableLayoutPlanner:208` (one edit or Save away).
8. Three sections still have a Save button and lose work on a tab switch,
   while everything else autosaves: RehearsalDinner (`:124-153`, single Save,
   unmounted at `Dashboard.jsx:1081`), TableLayoutPlanner (`:247`, no
   `beforeunload`), BarPlanner notes (`:438-448`, 800ms debounce with no flush
   on unmount). Isadora's rule: everything should autosave. Move all three
   onto `useAutosave`, which already flushes on unmount.
9. 149 raw `fetch(`${API_URL}...`)` calls bypass `apiFetch` (206 use it). Every
   raw loader turns a 401/500 into "nothing here yet": GuestList:696,
   AllergyRegistry:96, ClientInbox:43, PlanningChecklist:29, InspoGallery:30,
   PhotoBucket:268, BarPlanner:419, BorrowCatalog:58; admin profile load
   `Admin.jsx:958-1010` (ten `allSettled` calls, no ok check), AdminInbox:48,
   DirectMessagesPanel:25, KnowledgeBaseAdmin:62, UpcomingMeetings:19. Ratchet
   with an audit script like `audit-unfiltered-writes.mjs`.
10. Sage tells couples unreviewed AI guesses as fact. `:1582` selects
   `pending` notes and prints them under `CONFIRMED PLANNING DETAILS`
   (`:1587`), capped at the 30 newest so one Zoom import evicts older confirmed
   facts. Gmail attribution is by sender address, so an outsider's email can be
   repeated to the couple as confirmed.
11. Extraction is not idempotent and losses are permanent. Markers are written
    before extraction (3930 Gmail, 4964 SMS, 5055 calls, 5698 Zoom);
    `extractPlanningNotesAI:1412` returns `[]` on any error including 429, so
    the item is marked done with no notes and nothing recorded. Quo call
    transcripts continue past a failed marker (`5061-5073`) with no prior-note
    check. `reprocess`/`forceReprocess` re-run extraction and dedup is
    exact-string only (`1477`), so paraphrases land twice. Manual Zoom sync has
    no overlap guard and the marker is an upsert (`5460-5497`, `5700-5716`).
12. Failures never reach a human. `sync_jobs` `failed`/`last_error` rows are
    read only by `followSyncJob` while someone watches a click; a cron Zoom
    run that throws leaves its row `running` for ever (`14094`, no `fail()`);
    status lights are `!!token` / `!!QUO_API_KEY` (`5369`, `4442`); no "last
    synced / last error" per source in the UI; a dead Gmail grant produces
    "finished, 0 processed" (`4000-4002`, tokens not refreshed at `712-716`);
    the daily memo never mentions `sync_jobs` or `ingest_review`; the ingest
    queue is drawn below the content on 11 of 13 admin views
    (`Admin.jsx:1863`) with no header badge. Deepgram failure leaves
    `transcript` null, same as pending (`13577`, `lib/transcribe.js:65`).
13. Gmail fetches only the newest 20 hits per query, no `pageToken` loop
    (`3742-3746`); Quo texts 100 (`4899`), calls 50 (`5029`). A backlog older
    than the first page is permanently unreachable.
14. Unbounded selects still live on growing tables: `usage_logs` (`7697`),
    all `messages` (`10534`, feeds escalation and "last active"),
    `direct_messages` (`9802`, unread counts), per-wedding `planning_notes`
    (`10590`, `3058`), `ingest-review` (`6134`), zoom transcripts (`6257`).
    Also `loadData` in `Admin.jsx:756` re-downloads every Sage message after
    every sync, file and upload.
15. Timezone drift outside `shared/venue-time.js`: vendor offers hide from
    8pm ET (`8042`); Sage says the wedding is past the evening before
    (`2244`); "days away" one short (`3091`, `5252`); Zoom dedup key is
    `toLocaleDateString()` in server locale (`5789`); dashboard says "over"
    from 00:00 on the day (`Dashboard.jsx:76`, `:173`); checklist due dates
    and contract dates a day early (`PlanningChecklist.jsx:330`,
    `VendorChecklist.jsx:374`).
16. Admin profile state leaks between weddings: contract Q&A answer, upload
    result, collapsed categories, inject text are not reset in
    `viewWeddingProfile` (`Admin.jsx:932`). Raw `couple_names` in 12 places
    despite `weddingName()` (AdminInbox:192/256/268, review-queue select, Sage
    Help send-to), so two live weddings show a blank label in the very select
    used to file unplaced emails.
17. Admin attention signals are wrong. "Needs attention" is keyword matching
    ("help", "late", "lost") on Sage chat only (`adminUtils.js:2-6`), never
    on direct messages. "Last active" and "This Week" count only Sage chat
    (`AdminWeddingList.jsx:327`), so a couple with 40 direct messages shows
    "No activity". Calendly invitees matched by first-name substring
    (`UpcomingMeetings.jsx:113`).
18. The front door can half-fail. Join-by-code does the `profiles` insert from
    the browser (`Login.jsx:153-163`, `:197` unchecked), says "Account
    created!" on failure, and the couple lands on the "not linked" banner,
    which tells staff to use an Access tab that does not exist
    (`AdminWeddingList.jsx:301`); no admin route sets `profiles.wedding_id`.
    The browser also chooses its own `wedding_id`/`role` on insert.
19. Phone experience. iPhone lockout: the mandatory photo overlay promises
    HEIC (`Dashboard.jsx:1201`), the multer filter refuses it (`:50-61`), and
    the z-100 overlay has no skip and covers sign-out. Hover-only edit/delete
    on PlanningChecklist:339,
    WeddingParty:719, CeremonyOrder:124, MakeupSchedule:405,
    DecorInventory:127, internal notes (`AdminWeddingProfile.jsx:719`, no
    confirm); drag-only reorder with no touch handlers (CeremonyOrder:102);
    div toggles (RsvpSettings:107); phone section picker missing four sections
    and bouncing `/vendors` (`DashboardNav.jsx:147`); HoneyBook/Sheets links
    cannot be edited on a phone (`AdminWeddingList.jsx:355` `hidden sm:flex`).
20. Nothing runs automatically. No CI, no hook; `npm run audit`, lint, unit and
    Playwright are opt-in (the 18 Aug twenty-hour guest-list outage passed
    build and lint). `node-cron` is not in `server/package.json` and resolves
    only via the root tree. `xlsx 0.18.5` has unfixable prototype-pollution
    advisories and parses couple uploads; 30 `npm audit` findings, 21 high.
    Zero tests on auth, weddingAccess, RSVP submit, guest party model, Sage
    scoping; four `scripts/test-*.mjs` never run.

Server

  media delete ignores select error and orphans storage (`12339`, `12441`).

- Anthropic client has no timeout; contract text inlined uncapped in `/api/chat`.
- Unchecked reads that decide a limit: notification dedup `599`, inspo cap
  `7046`, walkthrough re-parent `9390`.

  (`3860-3864`); the one matcher that guesses rather than asks.

  (`5651-5654`); weddings read error ignored at `5516`.

  half-read doc that looks unread (`13288-13337`).

Security and ops

  2193, 6951). `lib/rsvp-confirmation.js` has the right `esc()`.
- `?preview=<weddingId>` on `/api/w/:slug` skips published and password gates
  (`12662-12682`).

  (`14420`); `/api/gmail-callback-debug:199` public.
- Storage keys use unsanitised filenames (`2774`, `7056`, `4087` sender
  controlled, `10822`); SVG allowed into public buckets.

  missing (`401`, `middleware/auth.js:10`); should fail at startup.
